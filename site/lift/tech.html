昇降・カメラの技術詳細

hve-system

昇降部とカメラ部の構成、走行部から独立させた設計、上下端と天井を守る仕様をまとめます。

構成

昇降部とカメラ部の2つのユニットで構成し、どちらも hve-system のソフトウェアで制御します（チーム内では昇降部を hf、カメラ部を ve と呼んで分担しています）。 カメラ部はバッテリーで動く無線ユニットです。

ユニット中身役割
昇降部（hf） ESP32、モータードライバ Cytron MD10C、パワーウィンドウモーター、下端リミットスイッチ、ロータリーエンコーダ OMRON E6A2-CW3C（ロープの巻き取り軸に直結） カメラ部を上下させる。昇降部の操作画面を配信する
カメラ部（ve） カメラ M5Stack UnitV2、Arduino UNO（UnitV2 と UART で接続）、ヨー用ステッピングモーター 28BYJ-48（ULN2003）、ピッチ用サーボ MG996R、上向き超音波距離計 SRF02（I2C）、モバイルバッテリー 映像を送り、向きを変え、天井までの距離を測る。カメラ部の操作画面を配信する
無線 走行部の Raspberry Pi が出すアクセスポイント 操作端末・昇降部・カメラ部をつなぐ

カメラ部では、UnitV2 が映像の配信と操作画面を受け持ち、Arduino UNO がモーターと距離計を動かします。 カメラ部は昇降部に昇降を命じ、そのとき天井までの距離を一緒に送ります。

操作画面は2つあります。ふだんはカメラ部の画面で、映像を見ながら昇降・向き・ズームをすべて操作します。 昇降部の画面は、カメラ部が無くても昇降機を動かせるようにするためのものです。 昇降部のモーターは走行部の駆動系と同じ電源系統です。

設計思想

HD-1走行部（th-system）から独立させる。互いに通信せず、走行禁止などの連動も設けない
HD-2操作画面は走行部と別に持つ
HD-3高さは人が映像を見て決める。盤ごとの高さの事前登録を前提にしない
HD-4昇降機の上に載せる部分は、ソフトウェアごと交換できるモジュールにする。昇降部は単体でも動かせる

HD-1 の帰結として、次のことを受け入れています。

  • 走行部の画面の非常停止では昇降機は止まらない（物理の非常停止ボタンは電源を共有しているので止まる）
  • 昇降機が上がったまま機体が走れてしまう（既知のリスクとして管理）
  • アクセスポイントを共有するので、映像が走行部の通信を圧迫しうる。映像の帯域に上限を設けて確かめる

上下端と天井の安全仕様

状況振る舞い
下端スイッチが押されている下降しない。上昇はできる
昇降の高さが上端の閾値に達した上昇しない。下降はできる（エンコーダでの実装と実機確認が済むまでは一時無効。画面に常に表示する）
天井までの距離が閾値以下上昇しない（ちょうど閾値でも止める）
天井が近すぎて測れない（約15cm未満）天井が近いとみなし、上昇しない
反射が返らない（約6m超）天井は遠いとみなし上昇を許す。画面に「天井: 範囲外」と出す
高さ・天井の距離が読めない・古い上昇しない。センサー故障、通信断、電池切れ、電源を入れてからまだ下端に着いていない（高さの原点が決まっていない）場合を含む
モーターに出力しているのにエンコーダが回らない止める。反対方向へは動かせる。ロープの外れ、エンコーダの故障、引っかかりを想定
同じ方向に動き続けた時間が上限を超えた止める。上限は全行程の約1.5倍（実測までは10秒）
昇降部の画面から操作している天井の距離を使わずに上昇を許す。人が見て守る（下端・上端・連続駆動の上限は効く）

天井の距離はカメラ部で測り、昇降機を動かすのは昇降部なので、判定は無線を挟みます。 値が届かないことを「近くない」と扱うと、通信が切れた瞬間に天井へ突っ込むため、届かない値は必ず「上昇しない」側に倒します。 天井の距離を使うかどうかは、命令がカメラ部から来たか昇降部の画面から来たかで、昇降部が決めます。

昇降の高さは、昇降機を引き上げるロープの巻き取り軸に付けたロータリーエンコーダの回転から求めます。 はじめは上向きの超音波距離計で測っていましたが、2026年10月にエンコーダへ切り替えました。昇降の速さもこのエンコーダで測って一定に保ちます。 下端スイッチが押されるたびに高さを0に取り直し、電源を入れた直後は、一度下端まで下げるまで上昇させません。

エンコーダが数えるのは巻き取りの回転で、昇降機そのものの位置ではありません。 下降中に昇降機が引っかかるとロープだけが繰り出され、表示と実際の位置がずれます。 このずれを検知する手段は無いため、連続駆動の上限と操作者の目で守ります。

非常停止

手段昇降機カメラの向き
機体の物理非常停止ボタン止まる（電源が切れる）止まらない（バッテリー給電）
走行部の画面の非常停止止まらない止まらない
本システムの画面ボタンを離せば止まる同左

パワーウィンドウモーターはウォームギアで自己保持するため、電源が切れても昇降機はその場で止まり、落下しません。

カメラ部への指令が途絶えたときは、ヨーは止まり、ピッチはその角度で保ちます。ピッチのサーボの力を抜くとカメラが倒れるためです。

PoC の結果

昇降機構（〜2026年9月）

3mの自動昇降を目標に、アルミ角パイプを3段に組んだ伸縮構造を試作しました。 はじめに使った直径2mmのステンレスワイヤーは、曲げ半径が30mm必要で、満たすには設計の全面的な変更が要るため見送りました。 柔らかい4mmのパラコードに替えて摩擦を減らし、巻取り機構を取り付けて自動で昇降できることを確認しました。

課題として、3段目が摩擦に負けて下がり切らない問題が残っており、全体の再設計が必要です。 試験場所の天井に当たるため、最大の長さはまだ確かめられていません。

カメラ部の見直し（2026年10月〜）

使える機器が増えたため、2026年10月に設計を見直しました。 カメラ部は Raspberry Pi 4 と Webカメラの組み合わせから、カメラを内蔵した小型コンピュータ M5Stack UnitV2 と、モーターを動かす Arduino UNO の組み合わせに変えています。

UnitV2 の実機調査結果
カメラの解像度1920×1080 は取れず、1280×720 の MJPEG（30fps まで）を使う。中央を切り出して 480p に作り直して配信する
映像の連続配信16分間、約8fps で一定。メモリは増えず、温度は 74〜75℃ で頭打ち
PC との無線の往復中央値 6.6ms、最大 12.6ms
UnitV2 ⇔ Arduino UNO（UART）往復 中央値 2.3ms・最大 4.2ms。2000回の応答で取りこぼし 0

この設計に沿って実装と実機での確認を進めています（2026年10月時点）。

プーリー固定具の強度

ロープの向きを変えるプーリーを支える3Dプリント部品について、SOLIDWORKS Simulation で強度を計算しました。 ふつうの昇降なら安全率 約3.4〜4.4 で足りますが、モーターが巻き上げの端で止まらずに引き続けると壊れる計算になるため、モーターを止める仕組みが要ります。 この結果から、材料の少ない検証用の形を採用し、モーターを止める仕組みを入れ、印刷の向きを変えて外周4周・充填率100%で印刷することにしました。 詳しくはプーリー固定具の強度検証にまとめています。

まだ決まっていないこと

  • 本システム自体の目標（走行部と同じ「接触0件」の水準を課すか）
  • 盤の前での停止に求める許容差。カメラの向きで補えるぶん、走行部への要求を緩められる見込み
  • 撮影した画像の保存・一覧まで含めるか
  • 上端の閾値、天井までの余裕の距離などの実測値
  • エンコーダの回転を高さに直す値（分解能・巻き取りの径）と、巻き太りによる高さのずれ
  • カメラ部のモバイルバッテリー（ピッチのサーボの大きな電流をまかなえるもの）

仕様・設計の全体は hve-system リポジトリ の docs/plan/spec/ にあります。
