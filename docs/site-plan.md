# サイト計画

ページ構成・掲載内容の計画と、未確定事項の管理。決まったら更新する。

## 目的・想定読者

- **目的**：発表会・展示の補足資料。展示ブースでは伝えきれない詳細を、来場者が後から（またはその場で）読めるようにする
- **想定読者**：発表会の来場者・審査員（技術的な関心がある人が中心）
- **想定導線**：展示パネルやポスターの QR コード → スマホで閲覧

### 背景（MIRS2602-DSGN-0001 より）

- 配電盤の立会試験で、お客様が盤の上面（高さ約3m）の構造を確認するのに脚立に登る必要がある
- お客様には年配の方もおり、転落によるけがのリスクが高い
- 協力企業との話し合いと工場見学を経てテーマを決定
- 当初構想には「試験中の音声を文字起こしして成績書・議事録へ自動入力する」機能もあった（現サイトでは扱っていない）

### この目的から導かれる設計方針

- **スマホで読むのが前提**。スマホ表示を先に作り、PC 表示はそれを広げる
- 冒頭で「何のロボットか」を一言で伝える。詳細は下にスクロールして読み進める構成
- 技術的な詳細（構成図、センサー、安全設計）はしっかり書く。ここが展示で伝えきれない部分
- ソースコード（GitHub）へのリンクを置き、さらに深く知りたい人が辿れるようにする
- QR コードを印刷した後は URL を変えられない → **独自ドメインを使うなら印刷前に決める**

## ページ構成

階層を下りるほど専門的になる3段階構成。各ページ右上の「表示灯」（3つのランプの点灯数）で詳しさを示す。

| 詳しさ | 読者 | ページ |
|---|---|---|
| ●○○ 概要 | 一般の来場者 | `site/index.html` |
| ●●○ しくみ | 興味を持った人 | `move/`（盤の前まで運ぶ）、`lift/`（盤の上を見る）、`records/`（試験を記録する）、`project/`（プロジェクトについて） |
| ●●● 技術詳細 | 技術者・審査員 | `move/tech.html`、`lift/tech.html`、`records/tech.html`、`lift/strength.html`（プーリー固定具の強度検証）、`project/development.html`（ソフトウェアの開発の進め方） |

書き分けのルール：

- **概要**：専門用語を使わない。数字は「約3m」のように実感できるものだけ
- **しくみ**：専門用語は初出で言い換える（例：LiDAR（レーザーで周囲の距離を測るセンサー））。結果の数値は代表的なものを少しだけ
- **技術詳細**：部品の型番、ソフトウェア構成、アルゴリズム、PoC の数値表、制限事項まで書く。出典のリポジトリへリンクする
- しくみページの最後に、1段深いページへのリンク（`.deeper`）を置く

機能の対応：

| 機能 | リポジトリ |
|---|---|
| 盤の前まで運ぶ | th-system |
| 盤の上を見る | hve-system |
| 試験を記録する | lr-system（議事録）、成績表アプリ（リポジトリ未確認） |
