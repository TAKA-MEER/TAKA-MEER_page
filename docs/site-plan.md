# サイト計画

ページ構成・掲載内容の計画と、未確定事項の管理。決まったら更新する。

## 目的・想定読者

- **目的**：発表会・展示の補足資料。展示ブースでは伝えきれない詳細を、来場者が後から（またはその場で）読めるようにする
- **想定読者**：発表会の来場者・審査員（技術的な関心がある人が中心）
- **想定導線**：展示パネルやポスターの QR コード → スマホで閲覧

### 日程

| 2026-11-07 | 発表方法の実証確認。一般の人の反応を見る | 初版を公開済みにしておく |
| 2026-12-12 | 学内発表（本番） | 11/7 の反応を反映した完成版 |

### 背景（MIRS2602-DSGN-0001 より）

- 配電盤の立会試験で、お客様が盤の上面（高さ約2.3m）の構造を確認するのに脚立に登る必要がある
- お客様には年配の方もおり、転落によるけがのリスクが高い
- 協力企業との話し合いと工場見学を経てテーマを決定
- 当初構想には「試験中の音声を文字起こしして成績書・議事録へ自動入力する」機能もあった（現サイトでは扱っていない）

### この目的から導かれる設計方針

- **スマホで読むのが前提**。スマホ表示を先に作り、PC 表示はそれを広げる
- 冒頭で「何のロボットか」を一言で伝える。詳細は下にスクロールして読み進める構成
- 技術的な詳細（構成図、センサー、安全設計）はしっかり書く。ここが展示で伝えきれない部分
- ソースコード（GitHub）へのリンクを置き、さらに深く知りたい人が辿れるようにする
- QR コードを印刷した後は URL を変えられない → **独自ドメインを使うなら印刷前に決める**

## ページ構成案

1ページ構成（スクロール型）で始め、内容が増えたらページを分ける。

1. **ヒーロー**：高見舎 / TAKA-MEER、「配電盤の上部を確認するロボット」、メインビジュアル（実機写真 or CAD）
2. **背景・課題**：なぜ配電盤上部の確認が必要か、人が行う場合の大変さ
3. **ロボットの全体像**：走行部＋昇降機＋カメラの2システム構成。独立させた理由
4. **使い方の流れ**：保管場所 → 試験場 → 盤前停止 → カメラ上昇 → 確認 → 次の盤へ
5. **走行系（th-system）**：構成、LiDAR、教示再生・追従、WebUI
6. **昇降・カメラ系（hve-system）**：昇降機構、ヨー・ピッチ、天井検知
7. **安全への取り組み**：G1 最優先、多重化、非常停止、明示操作の原則
8. **開発の進め方・進捗**：PoC → MVP、現在地
9. **チーム**
10. **ソースコード・クレジット**：GitHub リンク、VOICEVOX Nemo のクレジット
