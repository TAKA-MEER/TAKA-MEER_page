## 背景（DSGN-0001 POC構想）

- 協力企業との話し合いと工場見学を経て、立会試験の支援ロボットに決定
- 配電盤上部の確認は脚立が必要。盤は高さ約3m（DSGN-0001 の原文は「2.3mほど」だが、意図は「2,3m」＝2〜3m。チームの紹介では約3mで統一。2026-10-16 ユーザー確認）、お客様には年配の方もおり転落リスクが高い
- 試験結果を成績書に記録する間、お客様が待たされる
- 目的：試験をより安全・快適にし、企業イメージ向上と試験費用削減につなげる
- 当初コンセプト：昇降カメラ ＋ 従業員を追従しながら音声を文字起こしし、成績書・議事録に自動反映

## 走行系

### REPT-0001 追従走行（2026-08-17、校舎3階 約170m）

- 所要 10分50秒。緊急停止5回（すべて壁）、見失い再選択12回、乗り移り1回、ESP32ロスト1回、手動復帰5回
- 直線でも左右に約1m振れた。最高速度は約1m/s（当日のみ引き上げ。既定0.3m/s）
- 方針：追従を改善しつつ、教示再生走行を並行して確立

## 資料作成

### REPT-0004 / lr-system 議事録システム

- 構成：Windows ＋ Docker（minutes-app: FastAPI＋faster-whisper large-v3 ／ minutes-ollama: Ollama qwen3.5:9b）
- GPU：RTX 4060 Ti 8GB。STT と LLM は同時に載せず逐次切替
- 音声：ブラウザ MediaRecorder で WebM/Opus 5秒チャンク → WebSocket → ffmpeg 16kHz モノラル → Whisper
- 話者判定：自社側が BT イヤホン装着。BT マイク音量を50msフレームで記録し、直近60秒の分布から閾値を自動決定（adaptive方式）。正解率 0.80〜0.92 → 0.88〜0.99
- LLM：Stage1（6000文字ごとに要点JSON抽出）→ 名寄せ（プログラム）→ Stage2（JSONスキーマ制約で最終議事録）→ docx
- 完全ローカル。huggingface_hub の意図しない通信を検出し HF_HUB_OFFLINE=1 で遮断
- 検証：VOICEVOX の合成音声で模擬立会試験。短時間 約8.8分×12回、長時間 約3時間（139ターン、A盤・B盤）×3回

| 項目 | 短時間 | 長時間 |
|---|---|---|
| 文字起こし精度（1−CER） | 約85.1% | 約82.6% |
| 協議事項の再現率 | 7/7 | 11/11 |
| アクションの再現率 | 3/3 | 3/3 |
| VRAM | 5732〜6309MiB / 8188MiB | |

- モデル比較：qwen2.5:7b、qwen3:8b、qwen3.5:9b → qwen3.5:9b 採用（qwen3:8b は日付のハルシネーション）
- 長時間試験で見つかった不具合：無音区間のハルシネーション、Stage2 のコンテキスト超過、話題統合ロジック
- 制限：実音声・実工場は未検証。SNR 5dB で CER 約0.24、残響1.5秒で約0.35
