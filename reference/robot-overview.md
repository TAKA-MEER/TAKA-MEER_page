両システムは**意図的に独立**させている（互いに通信しない。共有するのは機体と無線 AP だけ）。
物理非常停止ボタンは電源系統を共有しているので、押すと走行部と昇降機が止まる（カメラ部のヨー・ピッチはモバイルバッテリ給電なので止まらない）。電源が切れても昇降機はウォームギアで自己保持し落下しない。

## 全体像

- 配電盤の上部をカメラで確認するロボット
- 走行部（th-system）が保管場所から試験場の盤前まで移動・停止し、その上に載った昇降機（hve-system）がカメラを持ち上げて盤上部を映す
- 試験場には納品前の製品（配電盤）が置かれている
- 運用者（試験員）は**原則 1 人で全作業が完結する**ことを目標にしている
- 操作はすべて WebUI（PC・タブレット、縦横両対応）

## 走行系 th-system

- クローラーロボット（走行部は CuGoV3）
- 構成：ESP32（モーター制御）＋ Raspberry Pi 4（LiDAR・中継・Wi-Fi AP）＋ PC（ROS2 Humble / Docker）
- PC は機体に載せず、無線で接続
- センサー：2D-LiDAR（RPLIDAR S1、360°、10Hz）、IMU、エンコーダ
- 機能：
  - 手動教示 → 教示再生（現在動いているデモ）
  - LiDAR による脚検知（DR-SPAAM）で試験員を追従
  - 地図作成（SLAM Toolbox）、Nav2 によるナビゲーション
  - 盤前への移動・停止
  - 音声アナウンス（VOICEVOX Nemo を使用。クレジット表記が必要）
- 安全設計：
  - 速度指令は必ず優先度つきの多重化（twist_mux）を経由する
  - 異常検知でモーター出力を即ゼロにして待機モードへ（ESP32 ウォッチドッグ 600ms が最終保証）
  - モード切替はすべて明示操作。人が押していないのに動き出す経路を作らない

### 目標（Spec.md §3）

| ID | 目標 |
|---|---|
| G1 | 人・物への接触 0 件、意図しない挙動 0 件（故障注入で検証）。**他のすべてに優先** |
| G2 | カメラ昇降が要求する許容差内に、手動微調整なしで停止できる |
| G3 | 地図作成＋盤登録が試験員 1 人で完結し、地図の手修正が不要 |
| G4 | 保管場所⇔試験場を、付き添う以上の負担なく移動できる |
| G5 | 往復＋準備＋試験を再起動なしで完走できる |

KPI は率ではなく回数で書く方針（例：「10 回中 10 回」）。

### 開発の進め方（Spec.md §4）

- PoC → MVP。実証実験でデータを得た時点で開発終了
- PoC では走行方式（全 7 方式）を削らず全部作って試験し、MVP で引き算する
- 採否の判断順：許可 → 完走率・介入回数 → 安全 → 期間内に作れるか

## 昇降・カメラ系 hve-system

- 昇降部：ESP32 ＋ モータドライバ Cytron MD10C ＋ パワーウィンドウモータ ＋ 下端リミットスイッチ ＋ 超音波距離計 HC-SR04
- カメラ部（無線ユニット）：Raspberry Pi 4 ＋ Web カメラ ＋ ヨー用ステッピングモータ 28BYJ-48 ＋ ピッチ用サーボ SG90 ＋ モバイルバッテリ ＋ 天井までの距離を測る超音波距離計 SRF02
- 高さは事前登録せず、**人が映像を見て決める**
- 上端・天井に近づくと自動で上昇停止
- 状態：PC でできる実装は完了、実機確認はこれから（2026-09-29 時点）

### 盤前での操作の流れ

1. 走行部が盤前に機体を止める
2. カメラ映像を見ながら昇降機を上昇させる
3. 操作者がよいと思ったところで止める
4. ヨー・ピッチで向きを合わせ、デジタルズームで盤上部を確認
5. 下降させて次の盤へ
